## 1. 从"显式评分"到"隐式反馈"

真实业务里,用户很少主动打分;更多的是点击、浏览、播放、购买——这些叫**隐式反馈**(implicit feedback)。隐式反馈只有"交互了"和"没交互"两种状态,没有"打 5 分还是 2 分"的细粒度。

MovieLens 是显式评分数据集(0.5~5.0),本阶段把它转成隐式正样本:

```java
Dataset implicit = all.filterRatings(4.0);  // Main.java:36
```

规则:**评分 ≥ 4.0 视为"喜欢"(正样本),其余忽略**。为什么选 4.0?因为 5 分制里 4、5 分通常代表明确的正面态度,3 分及以下更接近"无感/不喜欢"。

数据变化:

```
原始评分:              610 用户, 9724 物品, 100836 条评分
隐式正样本(>=4.0):     609 用户,  6298 物品,  48580 条交互
```

物品数从 9724 降到 6298,因为大量低分/冷门电影被过滤掉了。**这是业务侧最重要的变化:推荐的目标从"预测用户会打几分"变成"猜用户会不会喜欢"。**

## 2. BPR 的核心思想:正样本要排在负样本前面

对每一个观测到的正样本 `(u, i)`,BPR 问:

> 用户 u 对物品 i 的偏好,应该高于他对任意一个他没交互过的物品 j 的偏好。

用符号写就是:

```
x_ui  >  x_uj
```

`x_ui` 是模型给用户 u、物品 i 打的"偏好分数",和第 3 部 MF 的预测分类似,但不再有"评分"的含义。

**关键:我们不直接优化"x_ui 等于几",而是优化"x_ui 比 x_uj 大多少"。**

这就是 **pointwise(逐点,MF)vs pairwise(成对,BPR)** 的分水岭:MF 学"每个格子填几",BPR 学"两个物品谁该排前面"。

---

## 3. 负采样:从"没交互"里构造负样本

用户没交互过的物品成千上万,不可能把它们全部拿来比较。BPR 的做法是**负采样**(negative sampling):对每个正样本 `(u,i)`,随机抽几个用户没见过的物品 `j` 当负样本。

代码:`BprMF.java:96-103`

```java
for (int s = 0; s < negSamples; s++) {
    int j;
    do {
        j = rnd.nextInt(nItems);
    } while (hist.contains(itemIds[j]));
    update(u, i, j);
}
```

- `negSamples=5`:每个正样本配 5 个负样本。
- `hist` 是该用户在训练集里交互过的物品集合,负采样必须排除这些,否则会把正样本错当成负样本。
- 均匀随机采样:所有没交互过的物品概率相同。这是最简单的做法;工业界会用"按 popularity 加权"或"hard negative"等更复杂的策略,但本阶段先把基线跑通。

**一个具体例子**:假设用户 414 训练集里喜欢过《玩具总动员》《星球大战》《教父》。对正样本《星球大战》,负采样可能抽到《西雅图夜未眠》《勇敢者的游戏》《某部冷门纪录片》——这些就是他"没看过"的电影,模型要学到《星球大战》的分数高于它们。

## 4. BPR 损失函数与 SGD 更新

我们要让 `x_ui - x_uj` 尽量大。BPR 用 sigmoid 把它变成概率:

```
P(i >_u j) = σ(x_ui - x_uj) = 1 / (1 + exp(-(x_ui - x_uj)))
```

> **🔤 公式翻译**
> - **读作**:"用户 u 更喜欢 i 而不是 j 的把握有多大"。输入是两者分数差,输出被压到 0~1。
> - **没见过的符号**:`σ`(西格玛小写)= sigmoid 函数,作用只有一个——把任意数压进 0~1;`exp(t)` = e 的 t 次方(`Math.exp(t)`);`i >_u j` 读作"在用户 u 心里,i 排在 j 前面"。
> - **对应代码**:`BprMF.java:111` —— `1.0 / (1.0 + Math.exp(z))`(注意代码里算的是 `σ(-z)`,即"搞错的程度")。更细的讲解见 [第 1 部 §4](part-01-math.md)。

**sigmoid 长什么样**:

```text
        概率
        1.0 ┤           ╭────────
            │         ╱
        0.5 ┤       ╱
            │     ╱
        0.0 ┤────╯
            └──────┬──────┬──────►  x_ui - x_uj
                  -5     0     +5
```

- `x_ui - x_uj` 很大(正样本分数远高于负样本) → 概率接近 1,模型很满意;
- `x_ui - x_uj` 很小甚至为负 → 概率接近 0.5 或更低,模型搞错了,要大力更新。

BPR 的目标就是最大化这个概率,等价于最小化负对数似然 `L = -ln σ(x_ui - x_uj)`。

> **🔤 公式翻译**
> - **读作**:"`-ln` 把'把握'变成'惩罚'——把握越接近 1 罚得越少,越接近 0(彻底搞错)罚得越多"。所以最小化 L,就是逼模型把正样本排到负样本前面。
> - **没见过的符号**:`ln` = 自然对数,`-ln(x)` 在 x 从 0 到 1 时从"无穷大"降到 0;`L` 就是这个样本的损失。
> - **生活比喻**:考试"自信地答错"扣得最狠。这里的"自信"= 概率接近 0,"答错"= 正样本没排前面。

### 4.1 代码里的 `x_ui` 是什么

`BprMF.java:109`:

```java
x_ui = bI[i] + p[u] · q[i]
x_uj = bI[j] + p[u] · q[j]
z    = x_ui - x_uj = (bI[i] - bI[j]) + p[u] · (q[i] - q[j])
```

> **🔤 公式翻译**
> - **读作**:"`x_ui` 是给物品 i 打的分,`x_uj` 是给物品 j 的分,`z` 是两者的差"(z 越大,说明越把 i 排在 j 前面,越理想)。
> - **代数小技巧**:两个式子相减,公共的 `p[u]` 被提出来变成 `p[u]·(q[i] − q[j])`——这就是"提取公因式",不用展开每一项。
> - **对应代码**:`BprMF.java:109` —— `double z = (bI[i] - bI[j]) + dotDiff(p[u], q[i], q[j]);`

注意这里没有 `μ` 和 `b_u`:因为排序只关心"相对高低",全局均值和用户偏置对任意物品都一样,相减就抵消了。保留 `bI` 是因为不同物品的"热门程度"确实影响排序。

### 4.2 `sigmoidNeg` 就是 BPR 里的"误差信号"

`BprMF.java:111`:

```java
double sigmoidNeg = 1.0 / (1.0 + Math.exp(z));  // = σ(-z) = 1 - σ(z)
```

它表示"模型认为 i 应该比 j 高,但实际差距是 z,我错得有多狠"。

| `z = x_ui - x_uj` | `sigmoidNeg` | 含义 |
|---|---|---|
| 很大的正数 | ≈ 0 | 已经排对了,几乎不用更新 |
| 0 | 0.5 | 分不出高低,中等更新 |
| 很大的负数 | ≈ 1 | 排反了,狠狠更新 |

你可以把 `sigmoidNeg` 理解为第 3 部 MF 里 `e = 真实分 - 预测分` 的对应物:都是"误差越大,更新越狠"。

### 4.3 参数更新:三方拉扯

`BprMF.java:113-127`:

```java
bI[i] += lr * ( sigmoidNeg - reg * bI[i]);   // 正样本偏置↑
bI[j] -= lr * ( sigmoidNeg - reg * bI[j]);   // 负样本偏置↓

for (int f = 0; f < k; f++) {
    double puf = pu[f];
    double qif = qi[f];
    double qjf = qj[f];
    pu[f] += lr * (sigmoidNeg * (qif - qjf) - reg * puf);  // p 靠近 qi,远离 qj
    qi[f] += lr * (sigmoidNeg * puf         - reg * qif);  // qi 靠近 p
    qj[f] -= lr * (sigmoidNeg * puf         - reg * qjf);  // qj 远离 p
}
```

> **🔤 公式翻译**
> - **共同结构**:和第 3 部 MF 一模一样 —— `参数 ← 参数 + lr × (误差信号 − 正则拉回)`,只是"误差信号"从 `e` 换成了 `sigmoidNeg`。
> - **`bI[i] += ...` / `bI[j] -= ...` 读作**:"正样本 i 的偏置往上抬、负样本 j 的偏置往下压"。一个 `+=` 一个 `-=`,就是在拉开两者的分数差。
> - **`pu[f] += lr * (sigmoidNeg*(qif − qjf) − reg*puf)` 读作**:"用户向量朝'正样本减负样本'的方向走"——所以它同时靠近 `q_i`、远离 `q_j`。
> - **三个参数、同一个 `sigmoidNeg`**:这一次更新,用户向量 + 正物品 + 负物品同时动(第 3 部 MF 一次只动用户和物品两方)。
> - **对应代码**:`BprMF.java:113-127`。

几何直觉:

```text
        q[i] (正样本, 教父)
         ↑
         │  ← p[u] 往这边靠
         │
    p[u] ✳
         │
         │  → p[u] 被推离这边
         ↓
        q[j] (负样本, 某烂片)
```

- **`p_u` 同时干两件事**:往正样本 `q_i` 靠,离负样本 `q_j` 远;
- **`q_i` 往 `p_u` 靠**:既然用户喜欢我,我就该靠近他的口味坐标;
- **`q_j` 离 `p_u` 远**:用户不喜欢我,我就该离远点。

为什么 `pu[f]` 的更新是 `sigmoidNeg * (qif - qjf)`?因为目标是让 `p_u·(q_i - q_j)` 变大。第 3 部推过:**要让 `p·q` 变大,`p` 要沿 `q` 的方向走**。这里"目标方向"是 `(q_i - q_j)`,所以 `p_u` 沿"靠近 `q_i`、远离 `q_j`"的方向走。

### 4.4 一个具体数字例子

假设用户 `u=414`:

```text
正样本 i = 《教父》, 负样本 j = 《某烂片》

当前状态(只看第 0 维):
  bI[i] = 0.3,    bI[j] = -0.1
  p[u]  = [0.5, ...]
  q[i]  = [0.4, ...]
  q[j]  = [0.2, ...]

x_ui 部分 = 0.5 * 0.4 = 0.20
x_uj 部分 = 0.5 * 0.2 = 0.10

z = (bI[i] - bI[j]) + (0.20 - 0.10)
  = (0.3 - (-0.1)) + 0.10
  = 0.5

sigmoidNeg = 1 / (1 + exp(0.5)) ≈ 0.377
```

`z=0.5` 是正的,说明模型已经排对了(正样本分数更高),但差距不够大,还要更新。

更新 `p[u][0]`(设 `lr=0.02, reg=0.01`):

```text
pu[0] += 0.02 * (0.377 * (0.4 - 0.2) - 0.01 * 0.5)
       = 0.02 * (0.0754 - 0.005)
       = +0.001408
```

新的 `p[u][0] = 0.5014`。`p_u` 往正样本方向走了一小步。

```text
qi[0] += 0.02 * (0.377 * 0.5 - 0.01 * 0.4) ≈ +0.00369
qj[0] -= 0.02 * (0.377 * 0.5 - 0.01 * 0.2) ≈ -0.00373
```

- `q_i` 增加 → 往 `p_u` 靠;
- `q_j` 减少 → 离 `p_u` 远。

**一次更新,三个向量同时朝"让正样本赢"的方向挪了一小步。** 重复几万次,用户向量就会聚集在他喜欢的电影附近,不喜欢的被推远。

### 4.5 和第 3 部 MF 更新公式的对照

| | 第 3 部 MF | BPR-MF |
|---|---|---|
| 误差项 | `e = 真实分 - 预测分` | `sigmoidNeg = σ(-z)` |
| 偏置更新 | `bU += lr*(e - reg*bU)` | `bI[i] += lr*(sigmoidNeg - reg*bI[i])` |
| | `bI += lr*(e - reg*bI)` | `bI[j] -= lr*(sigmoidNeg - reg*bI[j])` |
| 隐向量更新 | `p += lr*(e*q_i - reg*p)` | `p += lr*(sigmoidNeg*(q_i - q_j) - reg*p)` |
| 用了几方参数 | 2 方(用户、物品) | 3 方(用户、正物品、负物品) |

结构完全一样:`参数 += 步子 * (误差信号 - 正则拉回)`。区别只是把"分数差"换成了 `sigmoidNeg`,把"两个向量"换成了"三方拉扯"。

这就是 BPR 的"拉扯":**把用户向量拉向喜欢的物品,推离不喜欢的物品**。

## 5. 为什么 BPR 的排序能比评分 MF 强

第 3 部 MF 的损失是 `(真实分 - 预测分)²`,它的"世界"里只有"已评分的格子"。用户没评分的电影对它来说是透明的,模型从没被告诉"这些应该排在后面"。

BPR 的损失是 `log(1 + exp(-(x_ui - x_uj)))`,它的"世界"里天然有成对的"正样本在上、负样本在下"。**每一个负样本都在告诉模型:这些没交互过的物品不应该排这么高**。

结果:

| 模型 | HR@10 | NDCG@10 | 覆盖率 |
|---|---|---|---|
| Popular | 0.0295 | 0.0149 | 1.0% |
| ItemCF | 0.0396 | 0.0186 | 10.8% |
| **BPR-MF(k=100)** | **0.0438** | **0.0205** | **15.3%** |

BPR-MF 超过了 ItemCF,而且覆盖率也更高(不会只推热门片)。这就是"目标函数对准了任务"带来的收益。

## 6. 两个关键超参

| 参数 | 代码位置 | 含义 | 本阶段取值 | 影响 |
|---|---|---|---|---|
| `negSamples` | `BprMF` 构造器 | 每个正样本配几个负样本 | 5 | 太少学不稳,太多训练慢;通常 1~10 |
| `filterRatings` | `Main.java:36` | 几分以上算正样本 | 4.0 | 阈值越高正样本越"纯净";太低会把无感样本混进来 |

`negSamples=5` 意味着训练数据量被放大了 5 倍(每个正样本产生 5 对比较),所以 BPR 训练比第 3 部 MF 慢。`Main.java` 里记录了训练耗时约 2.1s(ml-latest-small 上)。

## 7. 切分方式的变化:从 leave-one-out 到 time-split

前面(MF 阶段)用 leave-one-out(每个用户只留最新 1 条作测试),本阶段改成 `timeSplit(0.2, 5)`:每个用户按时间排序,前 80% 训练、后 20% 测试。

```java
TrainTestSplitter.Split split = TrainTestSplitter.timeSplit(implicit, 0.2, 5);  // Main.java:44
```

为什么换?因为隐式反馈下每个用户可能有很多条交互,只留 1 条测试指标方差大;time-split 每用户留多条,评估更稳定。`Evaluation.java:37-41` 也改成对每用户的多个测试物品分别算 HR/NDCG 再取平均。(切分的细节见 [第 5 部](part-05-evaluation.md)。)

## 8. 坑:把"所有评分"当正样本,BPR 反而更差

一开始没有 `filterRatings(4.0)`,直接把全部 10 万条评分当隐式正样本训练 BPR,结果 HR@10 只有 2.46%,还不如 ItemCF。

**根因**:3 分、2 分甚至 0.5 分的评分,对用户来说未必是"喜欢"。把它们当正样本,等于告诉模型"用户喜欢《某烂片》",负采样时再随便抽个没看过的电影说"这个不如《某烂片》"。标签本身就脏了,模型当然学不好。

**教训**:隐式反馈的"正样本定义"是业务问题,不是技术问题。MovieLens 里用 ≥4.0 当"喜欢"是领域惯例,但真实业务里可能需要结合播放完成率、停留时长、是否收藏等行为来定义。(完整复盘见 [附录 B §B.3](appendix/B-pitfalls.md)。)

---

## 9. BPR-MF 的局限

- 仍然是 O(物品数 × k) 的打分复杂度,**适合做候选集精排,不适合全量召回**。
- 冷启动问题依旧:新用户/新物品没有向量,只能退化成热门推荐。
- 均匀负采样假设"没交互 = 不喜欢",但很多时候"没交互 = 没看到",会引入偏差。后续可以引入更复杂的采样策略。

---

## 10. 本部结论

BPR 用一句话概括:**把"正样本排在负样本前面"当成训练目标,用 sigmoid 把它变概率、用负对数把它变损失,再用 SGD 让用户向量靠近喜欢的、远离不喜欢的。**

它证明了第 3 部那个"认知鸿沟"是可以跨过的:**只要把损失函数对准你真正要的东西(排序),模型的排序能力就能反超**。

但 BPR 的 `recommend` 仍是 O(物品数 × k)——**算法强了,工程瓶颈还在**。这就引出下一部要解决的两件事:**怎么判断谁好谁坏(评估)**,以及**怎么让模型跑得动(两级架构)**。
