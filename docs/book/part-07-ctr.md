## 1. 阶段三留下的缺口:精排得"不一样,且更强"

第 6 部 §9 的结论是:**两级架构要有效果,精排必须和召回"不一样、且更强"**。

但阶段三的所谓精排,用的是和召回 BPR 向量**同一套向量**(`二StageRecommender(vectorRecall, bpr, n)`),所以精排给的排序基本等于召回顺序,候选集开多大 HR 都纹丝不动——两级白绕一圈。

那"另一个信号"从哪来?

- 召回只能看见**用户向量**和**物品向量**这两个东西;
- 真实业务里还躺着一堆没用上的信息:**用户画像**(年龄、性别、活跃度)、**物品属性**(类目、价格、年份)、**上下文**(时段、设备、位置)。

把这些信息**交叉**起来,就能得到一个 BPR 看不到的排序信号。比如:

> 「这个用户 + 这类电影」的偏好,很可能和「那个用户 + 这类电影」完全不同;
> 光有"用户向量 × 物品向量"无法显式表达"用户 × 品类"这种二阶关系。

**特征交叉**,正是阶段四的核心。而 CTR 估计(预估"用户会不会点/看这个物品")是承载它的标准任务。

### 1.1 为什么 MF/BPR 通常做召回,FM 通常做精排?

这不是算法本身写死的规矩,而是**特征能力**和**计算量**共同决定的天然分工。

| 维度 | MF / BPR-MF | FM |
|---|---|---|
| 吃什么特征 |  mostly `用户ID × 物品ID` | `用户ID` + `物品ID` + 品类 + 年龄 + 时段 + 设备 …… |
| 交叉能力 | 只有 `用户 × 物品` 一种 | 任意二阶交叉:用户×品类、时段×类目、设备×类型 |
| 单次打分速度 | 向量内积,极快 | 要累加所有激活特征,慢一些 |
| 天然位置 | 召回:从百万候选里快速捞 | 精排:对几百候选精雕细琢 |

**MF/BPR 为什么适合召回?**

它只学两个向量:用户向量 `p_u` 和物品向量 `q_i`。打分就是 `p_u · q_i`,一个点积,算得飞快。线上可以把所有物品的 `q_i` 提前算好存起来,用户请求时只算一个 `p_u`,然后做最近邻检索(ANN)。**几百万物品也能在毫秒级扫完**。

代价是:它只能表达"这个用户和哪个物品气味相投",无法说"这个用户在周五晚上、用手机、对动作片的偏好"。所以它只能做粗筛。

**FM 为什么适合精排?**

召回已经把候选从几百万压到几百个,精排有时间"细嚼慢咽"。FM 把用户画像、物品属性、上下文全变成开关,自动学习它们的两两交叉。比如:

> 用户 1 和 Action 合拍 → Action 片加分;
> 周五晚上和恐怖片合拍 → 深夜恐怖片加分;
> 用户 1 + 周五晚上 + 手机 + Action → 四重组合再加分。

这些交叉让 FM 的预估更准,但也意味着每打分一次都要遍历所有激活特征。如果让它对几百万物品打分,延迟会爆掉;但对几百个候选打分,完全在可接受范围内。

> ⚠️ 这不是铁律。早期推荐系统也直接用 MF 做最终排序;现在也有 DSSM 这种"双塔"模型把 FM 思想用到召回。但在我们这门课的**两级架构**里,MF/BPR 是召回,FM 是精排,是最自然、最教学化的分工。

## 2. 第一步:把推荐问题改写成二分类

### 2.1 从"排多高"到"点不点"

前面几部我们一直在做 **ranking**(学"正样本排在负样本前")。CTR 估计换了个问法:

> 给定 (用户, 物品) 的特征,**点击的概率是多少?**

这是标准的**二分类**,标签 `y ∈ {0, 1}`:
- `y = 1`:用户真的看了这部电影(隐式正反馈);
- `y = 0`:用户没看。

两个问题的联系:模型输出点击概率 `p`,按 `p` 从高到低排,就是推荐排序。**ranking 和 CTR 是"同一个排序"的两种训练视角。**

### 2.2 负样本从哪来?——负采样

二分类需要正、负两类样本。但推荐数据里只有"用户看过什么",**没有"用户明确不想看什么"**。

所以跟 BPR 一样,我们**采样**出负例:对每个正样本 `(u, i)`,从用户没交互过的物品里随机挑几个当负样本。这套"正例 + 采样负例"的做法,是隐式反馈做 CTR 的通用起手式。

```text
正样本: (用户A, 电影N)  y=1
负样本: (用户A, 随机电影) y=0   ← 采样产生,不是真实数据
```

> ⚠️ 负采样是有讲究的:采得太少,模型没见过难负例;采得太多,训练变慢、正负失衡。
> 这个数字得实测——第 §5 节我们会看到它直接影响效果。

### 2.3 损失函数:log loss

二分类的标准损失是**对数损失(log loss)**,配上 sigmoid 把打分压到 (0, 1):

```text
ŷ = σ(x̂) = 1 / (1 + e^(−x̂))      ← x̂ 是模型原始打分,σ 把它变成概率
Loss = −[ y·ln(ŷ) + (1−y)·ln(1−ŷ) ]
```

对 `x̂` 求梯度,会得到一个极其简洁的结果:

| 🔤 公式翻译 |
|---|
| `∂Loss/∂x̂ = ŷ − y` |
| 人话:**预测概率和真实标签的差**。猜高了(ŷ>y)就往负方向调,猜低了就往正方向调。这就是整个梯度下降的驱动力。`FmRanker.java:194` 里的 `g = p - label` 就是它。 |

## 3. 第二步:把样本铺成"稀疏特征"

### 3.1 one-hot / multi-hot:一条样本长什么样

CTR 模型不直接吃"用户 42、电影 318",而是把每条样本铺成一长串 **0/1 特征**(one-hot / multi-hot):

| 特征域 | 取值 | 编码 | 圈 |
|---|---|---|---|
| 用户 ID | 42 | 只有"用户42"那一维是 1 | 用户 one-hot |
| 物品 ID | 318 | 只有"物品318"那一维是 1 | 物品 one-hot |
| 品类 | Action\|Thriller | "Action""Thriller"两维是 1 | 品类 **multi-hot** |

一部电影常属于多个 genre,所以品类是 multi-hot(多个位置同时为 1)。
`FmRanker` 的特征布局就是:用户段 + 物品段 + 品类段,一段挨着一段(`FmRanker.java:118-123`)。

### 3.2 二阶交叉:暴力做会爆炸

CTR 里最值钱的是**二阶交叉特征**:`用户 × 品类`、`用户 × 物品`……每两个特征相乘,各自学一个权重。

$$\hat{y} = w_0 + \sum_i w_i x_i + \sum_{i<j} w_{ij}\, x_i x_j$$

问题是**参数量**:若特征空间有 `n` 维,交叉项权重 `w_{ij}` 就有 `≈ n²/2` 个。我们的数据 `n ≈ 6000`,交叉权重就是近两千万个——而且绝大多数组合在数据里一次都没出现过,根本学不出来。

### 3.3 FM 的破局:交叉权重用两个隐向量的内积表示

FM(Factorization Machine)的关键一步:**不给每个 `w_{ij}` 单独学,而是给每个特征 `i` 配一个 `k` 维隐向量 `v_i`,用两个隐向量的内积当交叉权重**:

$$\hat{y} = w_0 + \sum_i w_i x_i + \sum_{i<j} \langle v_i, v_j \rangle\, x_i x_j$$

| 🔤 公式翻译 |
|---|
| 第一项 `w0`:全局偏置(所有样本共用一个底分)。 |
| 第二项 `Σ wᵢxᵢ`:**只保留取值为 1 的特征**的线性权重之和。每个特征一个 `w`。 |
| 第三项 `Σ⟨vᵢ,vⱼ⟩`:两两交叉。`⟨vᵢ,vⱼ⟩` 是两个 `k` 维向量点积,代表"特征 i 和特征 j 一起出现"的偏好。 |
| **参数量从 O(n²) 降到 O(n·k)**:每个特征只存一个 `k` 维向量,`k` 通常 8~64。 |

**为什么这不只是省参数?** 因为内积让隐向量**共享**:即使用户A从没和"惊悚片"同时出现过,只要用户A的向量和惊悚片的向量"对味儿"(在其它相似组合里被训练过),FM 也能给出合理的交叉估计。这叫 **对未见组合的泛化**——暴力 `w_{ij}` 做不到。

### 3.4 计算简化:完全平方恒等式

朴素实现要双重循环遍历所有特征对,是 `O(|S|²k)`(`S` 是激活特征集合)。用**完全平方恒等式**一秒化简:

$$\sum_{i<j} \langle v_i, v_j \rangle = \tfrac{1}{2}\Big( \big\|\sum_{f \in S} v_f\big\|^2 - \sum_{f \in S} \|v_f\|^2 \Big)$$

| 🔤 公式翻译 |
|---|
| 左边:所有特征对的交叉之和(要 O(\|S\|²) 次点积)。 |
| 右边:先把所有激活向量加起来,求它模长的平方;再减去每个向量自己模长的平方;除 2。 |
| **复杂度降到 O(\|S\|·k)**:只需对所有激活特征求和一次,再逐维算平方。`FmRanker.java:220` 的 `predict` 就是这么写的。 |

### 3.5 一个 2×2 的手算例子

光看公式还是虚,我们用一组 **编出来的小数字** 把打分过程走一遍。

假设只有:

| 用户 | 电影 | 品类 |
|---|---|---|
| 用户 1 | 电影 1 | Action |
| 用户 2 | 电影 2 | Comedy |

开关排成 6 维:

| 位置 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 含义 | 用户 1 | 用户 2 | 电影 1 | 电影 2 | Action | Comedy |

#### 参数(随手编的)

```text
w0 = -1.0

w = [0.3, -0.2, 0.5, -0.1, 0.4, -0.3]

v[0] 用户 1   = [0.2,  0.1]
v[1] 用户 2   = [-0.1, 0.3]
v[2] 电影 1   = [0.3, -0.1]
v[3] 电影 2   = [0.1,  0.2]
v[4] Action   = [0.4,  0.2]
v[5] Comedy   = [-0.2, 0.1]
```

#### 样本 A:(用户 1, 电影 1)

亮了的位置:0(用户1)、2(电影1)、4(Action)。

**线性分:**

```text
w0 + w[0] + w[2] + w[4]
= -1.0 + 0.3 + 0.5 + 0.4
= 0.2
```

**交叉分:**

```text
v[0] + v[2] + v[4]
= [0.2,0.1] + [0.3,-0.1] + [0.4,0.2]
= [0.9, 0.2]

‖[0.9,0.2]‖² = 0.9² + 0.2² = 0.85

‖v[0]‖² = 0.2² + 0.1² = 0.05
‖v[2]‖² = 0.3² + 0.1² = 0.10
‖v[4]‖² = 0.4² + 0.2² = 0.20
Σ‖v‖² = 0.35

cross = ½ × (0.85 - 0.35) = 0.25
```

**总分:**

```text
x = 0.2 + 0.25 = 0.45
p = σ(0.45) ≈ 0.61
```

#### 样本 B:(用户 1, 电影 2)

亮了的位置:0(用户1)、3(电影2)、5(Comedy)。

```text
线性分 = -1.0 + 0.3 + (-0.1) + (-0.3) = -1.1

v[0] + v[3] + v[5] = [0.1, 0.4]
‖[0.1,0.4]‖² = 0.17
Σ‖v‖² = 0.05 + 0.05 + 0.05 = 0.15
cross = ½ × (0.17 - 0.15) = 0.01

x = -1.1 + 0.01 = -1.09
p = σ(-1.09) ≈ 0.25
```

| 样本 | 亮的开关 | 线性分 | 交叉分 | 总分 | 点击概率 |
|---|---|---|---|---|---|
| (用户1, 电影1) | {0,2,4} | 0.2 | 0.25 | 0.45 | **61%** |
| (用户1, 电影2) | {0,3,5} | -1.1 | 0.01 | -1.09 | **25%** |

模型认为用户 1 更可能看电影 1,因为电影 1 本身更受欢迎(`w[2]=0.5`)、Action 品类加成更高(`w[4]=0.4`),而且用户 1、电影 1、Action 三个向量方向更合拍,交叉分 0.25 明显大于 Comedy 组合的 0.01。

> 这个例子里的 `w0`、`w`、`v` 都是编出来的;真实训练时它们从随机初值开始,通过 §4.3 的 SGD 更新慢慢收敛。

## 4. 第三步:手写 FM(代码走读)

源码只有 260 行,`src/main/java/tour/recsys/model/FmRanker.java`。它实现 `Ranker`(第 6 部那个精排接口),所以能直接塞进 `TwoStageRecommender`。

### 4.1 特征布局与参数

`fit()`(`FmRanker.java:91`)先建三套索引,并把它们排成连续的三段:

```text
[ 用户段: 0 .. nu-1 ][ 物品段: nu .. nu+ni-1 ][ 品类段: nu+ni .. ]
```

参数就三样,和公式一一对应:

| 参数 | 维度 | 对应公式项 |
|---|---|---|
| `w0` | 1 | 全局偏置 |
| `w[f]` | 特征数 | 线性项 `wᵢ` |
| `v[f][k]` | 特征数 × k | 交叉项的隐向量 `vᵢ` |

### 4.2 打分 `predict()`

给定激活特征集合 `S`(用户特征 + 物品特征 + 该片的品类特征):

```java
// FmRanker.java:220 起(节选)
double x = w0;
for (int f : s) {
    x += w[f];                      // 线性项 Σ wᵢ
    for (int d = 0; d < k; d++) {   // 累加所有激活隐向量
        sum[d]   += vf[d];
        sumSq[d] += vf[d] * vf[d];
    }
}
for (int d = 0; d < k; d++) {
    cross += sum[d] * sum[d] - sumSq[d];  // ‖Σv‖² − Σ‖v‖²
}
return x + 0.5 * cross;             // 完全平方恒等式,省掉双重循环
```

### 4.3 一次 SGD 更新 `update()`

这是全篇最需要盯紧的地方——**梯度的"旧值"纪律**,和第 4 部 BPR-MF 踩过的坑是同一个:

```java
// FmRanker.java:199(节选)
// 交叉项梯度需要 Σ_{g∈S} v_g,先算一次(必须用"旧值")
double[] sum = new double[k];
for (int f : s) {
    for (int d = 0; d < k; d++) sum[d] += v[f][d];
}
w0 -= lr * (g + reg * w0);
for (int f : s) {
    w[f] -= lr * (g + reg * w[f]);
    for (int d = 0; d < k; d++) {
        double vfd = vf[d];
        // ∂ŷ/∂v_f = Σ_{g≠f} v_g = sum − v_f
        vf[d] -= lr * (g * (sum[d] - vfd) + reg * vfd);
    }
}
```

| 🔤 公式翻译 |
|---|
| `g = p − label`:log loss 对 `x̂` 的梯度(§2.3 那张卡片)。 |
| `w0`、`w[f]` 的梯度就是 `g`(因为 `∂x̂/∂w0 = 1`、`∂x̂/∂w_f = 1`)。 |
| `v_f` 的梯度是 `Σ_{g≠f} v_g`:`sum` 是所有激活隐向量之和,减掉自己 `v_f` 就是"其它特征的向量之和"。 |
| `reg` 项是 L2 正则:每次更新都把参数往 0 拉一点,防止隐向量数值爆炸。 |
| ⚠️ **`sum` 必须用更新前的值算一次,再统一更新 `v`。** 若边更新边累加,梯度就用了被污染的值——这是手写 FM/MF 最经典的 bug。 |

FM 里也有 `⟨v_用户, v_物品⟩` 这个交叉,它**恰好就是第 3 部 MF 的 `p_u·q_i`**。所以可以这么说:

> **FM = 线性模型 + MF + 更多特征交叉。** 它把 MF 收编成了自己的一个特例,再往上加品类、上下文等交叉。经典 FM 论文里甚至说"FM 泛化了 MF / SVD++"。

## 5. 实验:FM 精排 vs BPR 精排

跑 `Stage4Main`(配方:`k=32`,负采样 10,60 轮;召回统一用 BPR 向量):

```bash
mvn -q compile
java -cp target/classes tour.recsys.Stage4Main data/ml-latest-small 10
```

### 表1 精排器横评(同一路向量召回 200,@K=10)

| 精排器 | HR@10 | NDCG@10 | 覆盖率 |
|---|---|---|---|
| 热门分(弱精排) | 0.0315 | 0.0155 | 2.6% |
| BPR 向量分(=召回) | 0.0438 | 0.0205 | 15.3% |
| **FM(品类交叉)** | **0.0442** | **0.0218** | 7.2% |

三个信号,三种命运:
- **热门分**:排序和召回完全无关且不个性化,最差;
- **BPR 向量分**:和召回是同一套向量,排序 ≈ 召回顺序,HR 就是召回的命中率,两级冗余;
- **FM**:引入了召回没有的"用户 × 物品 × 品类"交叉信号,**HR 和 NDCG 都超过了 BPR**。

但注意 **覆盖率**:FM 只有 7.2%,BPR 有 15.3%。FM 更偏好"大众口味",推的东西更集中。**效果和多样性是一对要权衡的指标**——这是新手最容易忽略的一课。

### 表2 特征消融:"多一类交叉"到底值多少?

同一份 FM,只改一个开关(有没有品类特征):

| FM 变体 | HR@10 | NDCG@10 | 覆盖率 |
|---|---|---|---|
| FM(仅 `用户 × 物品`) | 0.0418 | 0.0201 | 4.6% |
| FM(加 `品类` 交叉) | **0.0442** | **0.0218** | 7.2% |

关掉品类时,FM 只剩"用户 × 物品"一个交叉,**退化成一个带线性偏置的 MF**——效果和 BPR 差不多。

打开品类交叉后,模型多学到"这个用户爱看什么类型"的先验,又把效果推高了一点。**这就是特征工程的价值:同一套模型,喂进去的特征不同,效果就不同。**

> ⚠️ 但别迷信"特征越多越好"。我们调参时,品类交叉在有些配置下反而**拉低**了效果:品类是**粗粒度**先验,数据量小、负采样不够时容易过拟合,把它自己学成"热点放大器"。**每个特征都要单独做消融验证**,这就是表2存在的意义。

### 表3 好精排需要好召回

同一个 FM 精排,换不同的召回路:

| 召回 → FM 精排 | HR@10 | NDCG@10 |
|---|---|---|
| 热门召回 → FM | 0.0438 | 0.0216 |
| 向量召回 → FM | 0.0442 | 0.0218 |
| **多路召回 → FM** | **0.0446** | **0.0219** |

第 6 部的结论在这里再次被验证:**召回率是天花板**。多路召回把上限抬高,FM 才有空间把更好的物品排上来。精排再强,也救不回召回没捞到的物品。

### 表4 单级 vs 两级总账

| 方案 | HR@10 | NDCG@10 | 覆盖率 | 单次评估耗时 |
|---|---|---|---|---|
| BPR 单级(扫全库打分) | 0.0438 | 0.0205 | 15.3% | ~600ms |
| 向量召回 → BPR 精排 | 0.0438 | 0.0205 | 15.3% | ~240ms |
| 多路召回 → FM 精排 | 0.0446 | 0.0219 | 7.0% | ~280ms |

两件事同时成立:
1. **FM 精排(0.0446)确实比单级 BPR(0.0438)好**——精排和召回"不一样,且更强"时,两级架构终于产生了正收益;
2. **两级还更快**:召回只用算 200 个候选的分数,却拿到同等甚至更好的结果。

这就是阶段四真正交出的东西:**性能 + 效果,第一次同时赢**。

## 6. 再往上一层:深度 CTR 模型(理解级)

前面我们手写了 FM。FM 很强,但它有三个天花板,工业界的主流模型正是来捅破这三个天花板的:

| 天花板 | FM 的问题 | 对应的深度模型 |
|---|---|---|
| 只能做**二阶**交叉 | `用户 × 品类`可以,`用户 × 品类 × 时段`不会自动学 | MLP / Deep 路 |
| 用户兴趣是**静态**的 | 用户所有历史被压成一个固定向量 | DIN |
| 只盯着**点击**一个目标 | 标题党骗点击,点完就走 | 多目标学习 |

这一节不讲怎么手写(深度模型现在基本在 Python/TensorFlow 生态里实现),只讲**它们各自补了什么洞**。能回答"为什么需要它"比能背出结构更重要。

### 6.1 为什么需要神经网络?一个例子

假设你要预估:"周五晚上、北京、25 岁男性、手机 App、动作片《A》" 的点击率。

FM 能自动学到:
- `25岁男性 × 动作片`
- `北京 × 周五晚上`
- `手机App × 动作片`

这些都是**两两组合**的权重。但真实场景里真正起作用的,可能是 **三个甚至四个因素的组合**:

> 周五晚上 + 北京 + 动作片 = 下班地铁上刷爽片;
> 周五晚上 + 北京 + 文艺片 = 可能去电影院,手机上反而点得少。

FM 不会自动为这种"三因素组合"单独学一个权重——它需要人把三元组提前构造出来(比如 `周五晚_北京_动作片` 当做一个新特征),但组合爆炸,根本造不完。

**神经网络(MLP)的价值**:把特征 embedding 拼成一个大向量,通过多层非线性变换,自动捕捉这种高阶组合。它不需要人事先列出"周五晚 × 北京 × 动作片",网络自己会在数据里总结出这类模式。

代价是可解释性变差:FM 里 `v_动作片` 和 `v_男性` 的内积还能说出"这个组合重要";MLP 学到的东西是一堆权重矩阵,你很难直接翻译成人话。

### 6.2 Wide&Deep:老会计带实习生

Google 2016 年提出的 Wide&Deep,是工业界把"传统规则"和"神经网络"拼在一起的经典做法。我们用一个比喻理解它。

想象一个应用商店推荐团队:

- **Wide 路(老会计)**:手头有一本厚厚的账本,记满了高频规则。比如"安装过微信的人,80% 也会安装 QQ";"双十一期间,购物类 App 点击率比平时高 3 倍"。这些规则是人工写好的,或者线性模型从历史数据里直接数出来的。**它擅长"记忆"已经出现过的强规则。**
- **Deep 路(实习生)**:没见过那么多世面,但脑子灵活,会类比。比如"这个用户和那个用户画像很像,那个用户装了网易云音乐,这个用户可能也喜欢"。它通过 embedding + MLP 做**泛化**,处理没见过的组合。

结构很直观:

```text
   离散特征 ──► [ Wide 路:线性模型 ]  ─┐
                                     ├──► 相加 ──► σ ──► CTR
   特征embedding ─► [ Deep 路:多层MLP ] ─┘
```

最终 CTR = Wide 的线性分 + Deep 的神经网络分,一起喂进 sigmoid。

**为什么两路都要?**

| 只有 Wide | 只有 Deep |
|---|---|
| 能记住"装微信的人也装 QQ" | 可能抓不住这条已经被验证无数次的强规则 |
| 遇到新组合只能瞎猜 | 能从相似用户/物品里泛化 |

Wide&Deep 的核心思想:**记忆和泛化互补**,不是谁替代谁。

### 6.3 DeepFM:把老会计换成 FM

Wide&Deep 有一个隐形成本:Wide 路的那些规则(比如"微信→QQ")是人工写进特征工程的。业务越复杂,要维护的规则越多,越容易漏、容易冲突。

华为 2017 年提出的 DeepFM 说:**Wide 路别用人工规则了,直接用 FM。**

```text
     ┌───────── FM(二阶交叉) ─────────┐
输入─┤                                ├─► 相加 ─► σ ─► CTR
     └───────── Deep(多层MLP) ───────┘
```

- **FM 路**:自动做二阶交叉(就是 §3 讲的 FM,不用人工造 `用户 × 品类` 这类特征);
- **Deep 路**:MLP 自动学高阶交叉;
- **关键**:两路**共享同一份 embedding**。

**共享 embedding 为什么重要?** 假设物品 A 的 embedding 同时喂给 FM 路和 Deep 路。FM 路会告诉模型"物品 A 和谁搭配好",Deep 路会告诉模型"物品 A 在什么高阶场景下更容易被点"。同一份向量要同时满足两个任务,训练出来的 embedding 往往更稳定、更省参数。

DeepFM 现在是 CTR 领域最常用的基线模型之一,因为它把"人工特征工程"的压力降到了最低。

### 6.4 DIN:兴趣不是固定的,是看候选变的

前面所有模型(FM、Wide&Deep、DeepFM)都有一个共同假设:**用户的兴趣可以压缩成一个固定向量**。先把用户历史里的物品变成 embedding,然后求和或求平均,得到一个"用户兴趣向量",再去和候选物品算匹配度。

这个假设在很多时候是错的。想象一个用户的淘宝历史:

- 3 个月前买过奶粉(给孩子);
- 2 周前浏览过机械键盘;
- 昨天收藏了一条运动裤。

现在 App 给他推荐一款机械键盘。哪条历史应该被重视?显然是"2 周前的机械键盘"。"奶粉"虽然也是用户真实买过的东西,但和当前候选基本无关。

DIN(Deep Interest Network,阿里巴巴 2018)引入了一个直觉:**用户兴趣应该根据当前候选物品动态计算**。

```text
候选物品  ────────────►┐
                       │  注意力(和候选算相关度)
用户历史物品序列 ───────►┴──► 加权求和(动态用户兴趣) ──► MLP ──► CTR
```

它用**注意力机制**给历史物品打分:
- 候选是机械键盘 → "机械键盘"历史得高分,"奶粉"得低分;
- 候选是奶粉 → 反过来。

加权求和出来的"用户兴趣向量"不再是固定值,而是**针对当前候选**实时生成的。

**DIN 开启了一条主线:序列建模**。后来的模型不再把用户历史当静态袋子,而是当成时间序列,用注意力、RNN、Transformer 去建模"用户最近行为对当前决策的影响"。

### 6.5 多目标:点击不等于满意

CTR 预估的是"用户会不会点"。但真实业务里,**点击只是中间指标,不是最终目标**。

常见目标和它们的冲突:

| 目标 | 含义 | 只优化 CTR 会出什么问题 |
|---|---|---|
| **CTR** | 点不点 | — |
| **CVR**(转化率) | 点了之后买/看完没有 | 标题党骗点击,转化率为 0 |
| **时长 / 完播** | 看了多久 | 短视频点击率天然高,长文吃亏 |
| **留存 / 复访** | 还会不会再来 | 耸动标题短期点击高,长期用户厌倦 |

如果只盯 CTR,模型会把"封面吓人、标题夸张"的东西排前面,用户点进去发现上当,长期体验反而下降。

多目标学习的主流结构:

```text
        ┌─► CTR 头 ──► 点击概率
特征 ──► 共享底层 ──┤
        └─► CVR 头 ──► 转化概率
        └─► 时长头 ──► 观看时长
```

所有目标共享底层 embedding,上面接各自的任务头。线上排序时,再用一个业务公式把它们合成一个分,比如:

```text
最终分 = CTR × CVR × 时长权重 × 业务加权
```

### 6.6 一张演进梯子,看懂所有模型

把前面几部一起串起来,CTR 模型的演进不是谁比谁"高级",而是**每一步补上一个具体的洞**:

```text
MF/BPR ──► 只有"用户 × 物品"一个交叉
    │
    ▼ 缺:更丰富的二阶交叉
FM ──────► 自动做任意二阶交叉(用户×品类、时段×类目……)
    │
    ▼ 缺:三阶、四阶等高阶交叉
Wide&Deep ► 线性记忆 + MLP 高阶泛化
    │
    ▼ 缺:Wide 路还要人工写规则
DeepFM ──► 把 Wide 路换成 FM,少写特征工程
    │
    ▼ 缺:用户兴趣是静态向量
DIN ─────► 根据候选物品动态加权历史兴趣
    │
    ▼ 缺:只优化点击
多目标 ──► CTR + CVR + 时长 + 留存 一起学
```

读论文时,不要先背结构,先问三个问题:

1. **它补了上一个模型的哪个洞?**
2. **这个洞在业务里真实存在吗?** 比如小数据集上用 DIN 就是杀鸡用牛刀。
3. **它带来哪些新成本?** 比如 MLP 不可解释,多目标需要更多标签,注意力增加了在线 serving 复杂度。

### 6.7 一张表看懂演进

| 模型 | 解决什么 | 交叉方式 | 象限 |
|---|---|---|---|
| **MF / BPR**(第 3、4 部) | 只有 ID embedding | 只有 用户×物品 | 🟣 |
| **FM**(本部 §3-4) | 手工二阶交叉 | 隐向量内积,泛化到未见组合 | 🟣 |
| **Wide&Deep** | 记忆 + 泛化 | 线性(宽)+ MLP(深) | 🟠 |
| **DeepFM** | 免人工交叉特征 | FM + MLP,共享 embedding | 🟠 |
| **DIN** | 兴趣随候选动态变 | 历史序列 + 注意力 | 🟠 |
| **多目标** | 不只看点击 | 共享底层 + 多输出头 | 🟠 |

## 7. 本部最重要的结论

1. **CTR 估计 = 把推荐改成二分类。** 隐式反馈没有负例,用**负采样**造;损失用 **log loss**,梯度是漂亮的 `ŷ − y`。
2. **FM 的核心是"用隐向量内积表示二阶交叉",把参数从 O(n²) 压到 O(n·k),并泛化到未见组合。** 顺带收编了 MF。
3. **手写 FM 的坑还是"梯度的旧值纪律"**——交叉项梯度 `Σ_{g≠f} v_g` 必须用更新前的向量算。
4. **精排终于"和召回不一样,且更强"了**,两级架构第一次同时赢下效果和性能(§5 表4)。
5. **特征不是越多越好,覆盖率也不是越高越好。** 每个特征都要消融,每个指标都要权衡。
6. **深度 CTR 模型的演进主线:自动学高阶交叉(Wide&Deep / DeepFM)、动态兴趣(DIN)、多目标。** 记住"它替谁补洞",比记住结构更重要。
