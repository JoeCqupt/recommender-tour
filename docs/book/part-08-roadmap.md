## 2. 阶段 4:CTR 估计 —— 已经走过(回顾)

**核心问题**:光有 ID embedding 不够,怎么用上"用户/物品/上下文"的特征?

第 6 部留下一个关键缺口:**精排只是把召回的向量重算了一遍,不是"真正更强"的模型**。阶段 4 就是来补这个缺口——这一课已经在 **[第 7 部](part-07-ctr.md)** 亲手走完,这里只做回顾:

- **特征工程**:把用户 / 物品 / 品类铺成稀疏的 one-hot / multi-hot 特征。
- **特征交叉模型**:FM —— 用隐向量内积表示二阶交叉,参数量从 O(n²) 降到 O(n·k),还能泛化到未见组合。**已在 Java 里手写**(`FmRanker`)。
- **深度模型(理解级)**:Wide&Deep、DeepFM、DIN 的结构与动机——**留在 Python 生态里读,不手写**。
- **多目标**:不只优化点击(CTR),还要看转化(CVR)、时长、留存。

**产出**:手写 FM(Java,已在本仓库)+ 理解 DeepFM / DIN 的结构与动机。

**掌握标准**:能说清 FM 相比 MF 多解决了什么;能读懂 DeepFM 的"浅层 + 深层"双路结构。

> **技术象限变化:你第一次真正进入 🟠 深度学习。** 前六部的 MF/BPR 是"无隐藏层的神经网络";阶段 4 开始给它**加隐藏层、加特征交叉**——这才是大家口中的"推荐系统深度学习"。注意:**FM 本身仍属 🟣**(无隐藏层),DeepFM/DIN 才是 🟠。

## 3. 阶段 5:工程与服务 —— 已走过

**核心问题**:离线训好的模型,怎么变成一个真实的线上服务?

这一课已在 **[第 9 部](part-09-engineering.md)** 亲手走完,这里只做回顾:

- **离线训练 → 模型导出 → 在线 serving**:把 `EmbeddingStore`、`FmRanker` 和热门列表导出到 `models/` 目录,线上 `RecService.load()` 直接加载。
- **特征一致性**:模型文件里自带 `userIdx`/`itemIdx`/`genreIdx`,线上复用训练时的同一套索引。
- **冷启动**:训练集里没见过的用户走 `PopularRecall` 热门兜底。
- **A/B 实验**:按 `userId % 2` 把流量分到 FM 精排桶和 BPR 精排桶,对比两种精排信号。

**产出**:一个零第三方依赖的迷你推荐 HTTP 服务(`RecServer`),支持 `/recommend` 和 `/ab`。

**掌握标准**:能画出"离线 / 近线 / 在线"的数据流;能用 curl 调用本地推荐接口。

> 冷启动的具体策略(定时重训 / 内容特征 / 在线学习)在 [第 6 部 §8.2](part-06-two-stage.md) 和第 9 部已有完整讨论。

## 4. 阶段 6:论文与前沿 —— 带着手感去读

**核心问题**:怎么读懂并判断一篇推荐论文能不能落地?

你已经有"手感"了:知道召回和精排的分工、知道损失函数要对准目标、知道指标会骗人。带着这些去读论文,你会比空读快得多。

**读论文的方法**:先看**动机与贡献**(它解决什么问题、比谁好),再看**公式**(它是怎么做到的),最后看**实验与边界**(它在什么数据上有效、什么情况下会失效)。

**经典脉络(按顺序读 5–8 篇)**:

1. MF —— Koren 2009(第 3 部出处)
2. Item-based CF —— Amazon 2003 / Sarwar 2001(第 2 部出处)
3. BPR —— Rendle 2009(第 4 部出处)
4. NCF —— 神经网络做协同过滤
5. YouTube DNN —— 工业级召回的两塔结构
6. DIN —— 用户行为序列建模
7. 双塔召回 —— 大规模向量检索的标配
8. SASRec —— 序列推荐的自注意力

**掌握标准**:能在一页纸内讲清一篇论文"为什么提出、核心做法、适用边界"。

## 5. 语言边界:手写的边界在哪

| 内容 | 语言 | 理由 |
|---|---|---|
| 算法精髓:ItemCF / MF / BPR / **FM** | **纯 Java,零第三方依赖** | 亲手摸到每个梯度、每种数据结构,不被框架掩盖 |
| 深度模型:Wide&Deep / DeepFM / DIN | **Python**(PyTorch 等) | 带隐藏层与注意力的模型手写成本过高,90% 时间会花在写矩阵库而非学推荐 |

原则:**算法精髓用 Java 手写吃透,现代深度模型用 Python 读懂结构并实践。**

所以 FM 仍然留在 Java 里手写(它没有隐藏层,是 🟣);而 DeepFM/DIN 这些 🟠 模型从 Python 起步。第 7 部正是这条分界线上的最后一课。

## 7. 卡住的时候怎么办

如果后面某个阶段卡住了,回到这三条线,问自己一个问题:

> **我卡的是算法、系统,还是评估?**

- 卡在"这个公式为什么这样" → 算法线 → 回 [第 1 部](part-01-math.md) 补数学;
- 卡在"这个东西为什么要这么做" → 系统线 → 回 [第 6 部](part-06-two-stage.md) 想架构;
- 卡在"这指标到底说明什么" → 评估线 → 回 [第 5 部](part-05-evaluation.md) 看指标。

大多数"看不懂",不是因为你笨,而是因为**你缺的那块拼图在另一条线上**。
