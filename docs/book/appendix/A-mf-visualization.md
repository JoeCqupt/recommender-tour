## A.3 看图说话

- **彩色大点 = 电影**,颜色代表它的主类型(按 `movies.csv` 第一个 genre 划分)
- **灰色小点 = 用户**,活跃度最高的 30 人
- 横轴 / 纵轴 = 模型自己学出来的两个隐藏维度,**没有人类可解释的名字**

你能看到什么?

- **动作片(红色)** 整体偏向左下区域
- **喜剧/动画(蓝色/粉色)** 整体偏向右上区域
- 用户散落在空间里,有的离动作片簇近,有的离喜剧片簇近

这意味着模型确实抓到了一点"类型口味"的结构,但请注意:

> **这不是 genre 分类器。** 模型从来没看过"Action""Comedy"这些标签,它只是从评分模式里学到了这些簇。标签是我们事后贴上去帮助你看懂的。

**为什么不能指望 k=2 分得特别清楚?** 我们只给模型 **2 个维度**,它必须用这两个数概括所有口味。真实世界显然不止两个维度,所以簇之间有重叠很正常。如果设 `k=100`,分类会更细腻,但图就画不出来了。

## A.4 逐步拆解:一次真实预测的五步

下面是 `MfVisualizer` 对 **user 414** 的两部电影的真实计算输出。你能在 `MatrixFactorization.java:95` 找到完全对应的代码。

### A.4.1 电影 1:Heat (1995)

```
μ      = 3.5016   (所有人打分的平均水平)
b_u    = -0.0979  (user 414 的打分偏置)
b_i    = +0.4801  (这部电影的口碑偏置)
p_u    = [-0.7403, 0.1511]      ← 用户在品味空间里的坐标
q_i    = [-0.3531, -0.0596]     ← 电影在品味空间里的坐标
p_u·q_i= 0.2524                  ← 坐标点积 = 口味匹配分
r̂      = 3.5016 + (-0.0979) + 0.4801 + 0.2524 = 4.1361
真实评分 = 3.0
误差    = -1.1361
```

**解读**:模型预测 user 414 会给《Heat》打 **4.14 分**,但他实际只打了 **3.0 分**。预测偏高了。

为什么偏高?看坐标:

- 用户的坐标 `[-0.74, 0.15]` 和电影的坐标 `[-0.35, -0.06]` 方向大致一致(都在左侧),所以点积是正的 0.25。
- 加上电影本身的口碑偏置 `b_i=+0.48`(这片子整体口碑不错),预测就被拉到了 4.1。
- 实际用户比模型以为的"更不买账",所以误差为负。

### A.4.2 电影 2:Grumpier Old Men (1995)

```
μ      = 3.5016
b_u    = -0.0979
b_i    = -0.2244                  ← 这部电影口碑偏置为负
p_u    = [-0.7403, 0.1511]
q_i    = [0.1741, 0.1884]         ← 这部电影在右侧,和用户方向不一致
p_u·q_i= -0.1004                  ← 点积为负,口味不匹配
r̂      = 3.5016 + (-0.0979) + (-0.2244) + (-0.1004) = 3.0788
真实评分 = 4.0
误差    = +0.9212
```

**解读**:模型预测 **3.08 分**,实际用户打了 **4.0 分**。预测偏低了。

为什么?用户坐标在左侧(`-0.74`),电影坐标在右侧(`0.17`),两者方向相反,点积是负的 `-0.10`。模型以为 user 414 不喜欢这部喜剧片,但他实际给了 4 分 —— 说明仅用二维坐标概括口味会犯错,也印证了 MF 的 HR@10 只有 2% 的原因:**它学的是评分预测,不是"能不能把用户真正喜欢的电影排进前 K"**。

### A.4.3 公式与代码的一一对应

```
r̂_ui = μ + b_u + b_i + p_u · q_i
```

代码 `MatrixFactorization.java:95`:

```java
double pred = mu + bU[u] + bI[i] + dot(p[u], q[i]);
```

- `mu` → μ
- `bU[u]` → b_u
- `bI[i]` → b_i
- `dot(p[u], q[i])` → p_u · q_i

就是这么直接。

## A.5 手写 MF 训练循环的六个灵魂问题

第一次看 `MatrixFactorization.java` 的训练循环时,通常会被几个细节卡住。这里用大白话 + 具体数字回答。

### Q1:为什么 `Random rnd = new Random(42)`?42 有特殊含义吗?

**没有特殊含义,它只是一个"随机种子"**。换成 `0`、`1`、`2024` 都行。

作用:**让每次运行得到完全一样的随机数序列**。这样隐向量初始化、`shuffle` 顺序都固定,实验结果可复现。调参时必须固定种子,否则你分不清指标变化是参数带来的,还是随机波动带来的。

上线前可以改成 `new Random()`(用当前时间当种子),但每次结果会略有不同。

### Q2:`INIT_STD = 0.01` 是怎么定的?为什么不能是 0 或 1?

`INIT_STD` 是隐向量初始值的"抖动幅度"。代码里:

```java
p[u][f] = rnd.nextGaussian() * INIT_STD;
```

生成的是均值为 0、标准差为 0.01 的随机数,大部分落在 `[-0.01, +0.01]` 之间。

| 取值 | 后果 |
|---|---|
| `INIT_STD = 0` | 所有隐向量都是 0,`p·q = 0`,梯度永远为 0,模型 stuck。这叫**对称性无法打破**。 |
| `INIT_STD = 1.0` | 初始值太大,`dot(p,q)` 可能几十,预测分 `pred = 3.5 + 50 = 53.5`,误差爆炸,训练直接飞掉。 |
| `INIT_STD = 0.01` | 够小,初始预测接近 `mu`;不为 0,能打破对称。是社区默认的稳妥经验值。 |

### Q3:`lr`、`reg` 为什么取 0.01、0.02?

这两个都是**经验超参**,没有唯一正确答案。

- **`lr`(学习率)**:每次沿梯度走的步长。对 MovieLens 这种评分 0.5~5.0 的数据,误差 `e` 通常在 -2~+2 之间,乘以 0.01 后每次更新 0.0x 级别,属于"小碎步稳步下山"。
- **`reg`(正则强度)**:把参数往 0 拉的力。0.02 是"轻轻拉住",既防止参数爆炸,又不至于把隐向量压平。

`reg` 的具体对照见 [附录 B §B.2](B-pitfalls.md):

| reg | RMSE | HR@10 |
|---|---|---|
| 0.00 | 0.9896 | 0.0197 |
| 0.02 | 0.9664 | 0.0197 |
| 0.05 | 0.9556 | 0.0082 |
| 0.10 | 0.9567 | 0.0000 |

`reg` 越大,参数越被压向 0,模型越保守,RMSE 可能更好看,但排序能力被压没了。

### Q4:训练循环到底在干什么?一行行拆一下

```java
for (int epoch = 0; epoch < epochs; epoch++) {
    Collections.shuffle(data, rnd);           // ① 每轮打乱顺序
    for (Rating r : data) {                   // ② 一次只看一条评分
        int u = userIdx.get(r.userId());
        int i = itemIdx.get(r.movieId());
        double pred = mu + bU[u] + bI[i] + dot(p[u], q[i]);  // ③ 算预测
        double e = r.rating() - pred;         // ④ 算误差
        bU[u] += lr * (e - reg * bU[u]);      // ⑤ 更新偏置
        bI[i] += lr * (e - reg * bI[i]);
        double[] pu = p[u];
        double[] qi = q[i];
        for (int f = 0; f < k; f++) {
            double puf = pu[f];               // ⑥ 先存旧值!
            double qif = qi[f];
            pu[f] += lr * (e * qif - reg * puf);  // ⑦ 更新 p
            qi[f] += lr * (e * puf - reg * qif);  // ⑧ 更新 q
        }
    }
}
```

- ① `shuffle`:避免数据顺序引入偏差;
- ② 一次一条:SGD 的 "Stochastic",看完一条就更新;
- ③④ 算预测和误差 `e = 真实分 - 预测分`;
- ⑤ 偏置更新:`e` 推它往拟合方向走,`-reg*bU` 把它往 0 拉;
- ⑥ 存旧值:防止 `p` 更新后影响 `q` 的梯度,这是手写 MF 最经典的 bug;
- ⑦⑧ 隐向量更新:沿着对方向量的方向走,让点积变大/变小。

### Q5:更新公式里为什么 `pu[f]` 要乘 `qif`?

因为我们要改变 `p·q`:

```text
p · q = p[0]*q[0] + p[1]*q[1] + ... + p[k]*q[k]
```

如果让 `p[0]` 增加 `Δ`,内积会增加 `Δ * q[0]`。所以**让 `p[0]` 沿着 `q[0]` 的方向走,内积增加最快**。

公式上:

```text
p_new = p + α * q     (α 是小正数)
```

对应分量就是:

```text
p[f] += α * q[f]
```

代码里 `α = lr * e`:

- `e > 0`:预测偏低,要增大内积,`p` 向 `q` 靠近;
- `e < 0`:预测偏高,要减小内积,`p` 向 `q` 反方向移动。

### Q6:为什么内积变大 = 夹角变小?

内积公式:

```text
p · q = |p| × |q| × cos(θ)
```

假设长度不变,只看 `cos(θ)`:

| 夹角 θ | cos(θ) |
|---|---|
| 0°(同向) | 1.0(最大) |
| 45° | 0.707 |
| 90°(垂直) | 0 |
| 180°(反向) | -1.0(最小) |

夹角越小,`cos(θ)` 越大,内积越大。

具体例子:

```text
p = (1, 0), q = (0, 1)    夹角 90°, p·q = 0

把 p 往 q 方向推一点:
p_new = (1, 0.1)          夹角变小, p_new·q = 0.1

再推近一点:
p_new = (0.2, 1.0)        夹角更小, p_new·q = 1.0
```

所以 SGD 让 `p` 沿着 `q` 的方向走,本质就是让它们的夹角变小,从而让内积变大。
