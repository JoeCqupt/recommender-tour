# 附录 E:冷启动策略速查

> 冷启动不是"算法不够先进",而是**没有数据时怎么安全兜底**。
> 它的解决方案通常不是某个模型,而是一组"降级的策略 + 流量扶持机制"。

---

## E.1 新用户冷启动

训练集里没出现过的用户,`EmbeddingStore.userVector(userId)` 会返回 `null`。
此时不能硬算点积,必须走兜底。

### E.1.1 热门兜底(项目已实现)

**做法**:直接推全站最热门的物品。

**代码对应**:[`PopularRecall.java`](../../src/main/java/tour/recsys/recall/PopularRecall.java) 与 [`RecService.java`](../../src/main/java/tour/recsys/serve/RecService.java)。

**优点**:简单、稳定、不会空结果;所有系统必备。
**缺点**:没有个性化,容易让用户觉得"千篇一律"。

> 阶段五的 `RecService` 就是这样处理的:新用户没有向量 → 直接走 `PopularRecall`。

### E.1.2 按最少画像信息推荐

用户注册时通常能拿到一些基础信息,把它们当特征喂给 FM:

| 能拿到的信息 | 推荐策略 |
|---|---|
| 性别、年龄、城市 | 按人群推该人群热门 |
| 设备型号、渠道来源 | 按设备/渠道偏好推 |
| 地理位置 | 推附近热门 / 本地化内容 |
| 时间、场景 | 推当前时段热门(早餐、夜宵) |

**和项目的结合**:在 [`FmRanker.java`](../../src/main/java/tour/recsys/model/FmRanker.java) 里加入用户画像特征,FM 会自动学出"男性用户偏爱动作片"这类权重。

### E.1.3 引导式冷启动

**做法**:注册后让用户选 3-5 个兴趣标签。

**优点**:一上来就有明确信号。
**缺点**:增加注册流失率;用户可能乱选。

**典型产品**:网易云音乐、B站、知乎的"选择你感兴趣的领域"。

### E.1.4 借相似用户的数据

**做法**:虽然没有该用户的历史,但找到画像最像的老用户,先推那些老用户喜欢的。

**本质**:UserCF 的变体,用画像替代行为计算相似度。
**局限**:画像粒度不够时效果一般。

### E.1.5 探索利用(Bandit)

**做法**:新用户来了,先给一批"探索物品",根据实时反馈快速调整。

**常用算法**:Epsilon-Greedy、Thompson Sampling、UCB、LinUCB。

**优点**:能快速发现用户真实兴趣。
**缺点**:早期体验可能不稳定,需要产品能容忍一定噪声。

### E.1.6 内容先行的场景

如果用户是带着明确上下文进来的(比如搜索了一个词、点了一个类目),直接利用当前上下文:

- 搜索 query 扩展
- 当前浏览物品的相似物品
- 当前页面类目下的热门

## E.2 新物品冷启动

新物品更麻烦:系统没见过它,没有交互历史,无法学习向量。

### E.2.1 先"养"一段时间再进推荐池

**做法**:新物品上线后先不给推荐流量,等积累到一定点击量后再进入模型。

**优点**:避免模型被噪声污染。
**缺点**:新物品永远拿不到初始流量,必须配合下面的方法一起用。

### E.2.2 内容特征推荐

**做法**:用物品的标题、类目、标签、描述等属性特征做推荐。

**例子**:
- 新电影《流浪地球3》→ 推给看过《流浪地球1/2》的用户。
- 新商品"iPhone 16 手机壳"→ 推给浏览过 iPhone 16 的用户。

**和项目的结合**:FM 可以直接把物品内容特征加入特征向量。新物品没有历史交互,但只要有类目/标签,就能打分。

### E.2.3 继承相似物品的向量

**做法**:找到最相似的老物品,让新物品继承它的 embedding。

**相似度来源**:内容特征(类目、标签、文本、图片)。

**优点**:立刻能进入向量召回。
**风险**:找错了相似物品会误导一群用户。

### E.2.4 新物品流量扶持

**做法**:在召回或排序阶段给新物品额外加分,分数随时间衰减。

```text
finalScore = modelScore + newItemBoost · decay(daysSincePublish)
```

**目的**:让新物品有机会曝光,收集反馈。
**难点**:boost 加多了伤害用户体验,加少了没效果。

### E.2.5 创作者/店铺维度兜底

**做法**:如果新物品的创作者/店铺已经有其他热门物品,先用创作者维度推荐。

**适用场景**:UGC 平台、电商平台。

### E.2.6 在线学习 / 元学习

- **在线学习**:新物品一有交互就立即更新模型。
- **元学习**:让模型学会"如何快速适应新物品"。

**特点**:成本高,通常是大厂才会上的方案。

## E.3 在阶段五架构里怎么落地

当前架构:

```text
用户请求 → VectorRecall(200) → FmRanker/BprRanker 打分 → Top-N
              ↑
        冷启动用户没有向量 → 直接走 PopularRecall 热门兜底
```

| 场景 | 落地方式 |
|---|---|
| 新用户没有向量 | `VectorRecall` 返回空,`RecService` fallback 到 `PopularRecall` |
| 新用户有注册信息 | 把性别/城市/时间做成特征,FM 精排给这些特征学权重 |
| 新物品没有向量 | 用内容特征直接输入 FM;或在召回层加一路 ContentRecall |
| 新物品需要曝光 | 排序时加 `newItemBoost`,例如前 7 天 +0.5 分 |
| 系统完全没有数据 | 纯 `PopularRecall` 兜底 |

---

## E.4 关键认识:冷启动是权衡,不是算法

| 系统规模 | 推荐策略 |
|---|---|
| 流量小 | 热门兜底 + 内容相似度就够了 |
| 流量大 | 必须做 Bandit / 新物品扶持 / 在线学习,否则内容生态会枯竭 |
| 内容平台 | 新物品冷启动是核心问题 |
| 电商平台 | 新用户冷启动更关键,因为用户生命周期短 |

**一句话**:冷启动没有"最佳算法",只有"在当前数据量和产品容忍度下最稳的兜底"。
